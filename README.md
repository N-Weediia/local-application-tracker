# Local Application Tracker

一个零云端依赖的本地求职投递管理程序：管理候选企业、记录投递/测评/笔试/面试进展，并通过本机 IMAP 连接同步主流邮箱中的招聘邮件。

## 功能

- 推荐区最多显示 5 家未投递企业；勾选即归档并补入新的企业，跨批次、重传简历、修改偏好和刷新页面都不会复用已投递企业。
- 岗位推荐以用户上传的简历文本为输入：浏览器本地提取分类标签和原文技术术语，用于匹配目录中的建议岗位方向；不是大模型语义推荐，也不包含实时岗位爬虫。
- 支持大厂、央企、国企、知名企业、融资初创偏好，以及最低融资轮次和融资信息核实要求。
- 支持最多 5 个目标城市和长三角、珠三角等地区偏好。
- 历史记录、当前批次已勾选项、已投递 ID 和招聘进展邮件在首次打开新版时自动迁移。NIO/蔚来、小鹏/小鹏汽车等别名映射到同一企业，邮件仅按主题、发件人或企业域名匹配，正文偶然提及的企业不作为投递依据。
- 可以在推荐区批量登记已有投递，名称不在当前目录内也会保存，后续扩充目录时继续排除。
- 进展状态：待投递、已投递、测评、笔试、面试、Offer、拒绝。
- 本地 `localStorage` 保存状态，支持 JSON 导入/导出。
- 邮箱同步只在本机执行，不把账号密码上传到第三方服务，也不自动发送、转发或删除邮件。
- 通过通用 IMAP + 预置参数支持 Gmail、Outlook/Microsoft 365、QQ 邮箱、网易 163、阿里云企业邮箱和自定义 IMAP。
- 内置合成演示邮件和公开企业目录；公开仓库不包含用户简历、用户投递清单、真实私人邮件或登录令牌。

## 企业目录与耗尽行为

目录当前包含 80 家企业；2026-10-19 再增补 30 家，覆盖智能驾驶、服务机器人、工业视觉、控制软件、传感器和央企研发单位。企业类型偏好和原有已投递排除记录继续生效，更新目录时会保留尚未投递的候选并补足席位。

最近两批公开增补数据为 [`2026-10-19（30 家）`](data/company-updates/2026-10-19.json) 和 [`2026-10-18（23 家）`](data/company-updates/2026-10-18.json)，也可下载后通过“补充企业目录 JSON”导入已有安装。每条保留招聘入口、来源、核对日期和开放情况说明；导入同一批数据不会增加重复企业。个别来源是企业发布在高校就业网的招聘简章，已在数据中保留原始发布页。

岗位名称是根据业务领域给出的检索方向；招聘入口能访问不代表当前有该岗位，也不代表满足特定毕业届别和地点要求。部分门户仍展示旧届别，或暂时只见其他职类，这些情况记录在每条数据的 `availability` 中。明确列出 2027 届岗位的官网包括虹软、中望、百度及阿里巴巴等，最终以投递时的职位详情为准。

剩余未投递企业不足 5 家时只展示真实余量；全部处理后显示“目录已全部处理”，不会拿已投递企业凑足 5 家。页面显示目录总量、已排除数量和符合偏好的未投递数量。

点击“补充企业目录 JSON”可增补本机目录。文件为 JSON 数组，每项必须包含 `company`、`city`、`role`、`url`，可包含 `id`、`region`、`tags`、`aliases` 和 `profile`。例如：

```json
[
  {
    "id": "example",
    "company": "合成示例企业",
    "city": "上海",
    "region": "长三角",
    "role": "软件开发",
    "tags": ["cpp", "python"],
    "url": "https://example.com/careers",
    "profile": {"type": "知名企业", "funding": "unknown", "verified": false}
  }
]
```

自定义目录只在本浏览器保存，并包含在进度 JSON 导出内。旧数据迁移前会在同一浏览器中额外保存一份 `local_application_tracker_v2_before_dedup3` 备份。

## 本地运行

需要 Python 3.10 或更高版本，不需要安装第三方依赖。

```powershell
cd job-application-tracker
python server.py
```

然后打开 <http://127.0.0.1:8787>。Windows 用户也可以双击 `start.cmd`，或在 PowerShell 中运行 `./start.ps1`。

打开后先在“上传你的简历”区域选择自己的 `.md`/`.txt`/`.html` 文件，或粘贴简历文本，再点击“根据简历生成推荐”。推荐结果中的命中标签和匹配分会随简历内容变化；不上传简历时只显示演示候选池。

## 邮箱配置

在“邮箱同步”页选择提供商，填写邮箱账号和**授权码/应用专用密码**。程序只在当前进程内使用密码，关闭服务后不会保存。

| 提供商 | IMAP 服务器 | 端口 | 说明 |
|---|---|---:|---|
| Gmail | `imap.gmail.com` | 993 | 使用应用专用密码或 OAuth；普通密码通常不可用 |
| Outlook / Microsoft 365 | `outlook.office365.com` | 993 | 由租户策略决定，优先使用 OAuth 或应用专用密码 |
| QQ 邮箱 | `imap.qq.com` | 993 | 在邮箱设置中开启 IMAP 并生成授权码 |
| 网易 163 | `imap.163.com` | 993 | 在邮箱设置中开启 IMAP 并生成客户端授权密码 |
| 阿里云企业邮箱 | `imap.qiye.aliyun.com` | 993 | 企业管理员可能需要先开放 IMAP |
| 自定义 | 手动填写 | 手动填写 | 适用于学校、公司或其他 IMAP 服务 |

不同邮箱的安全策略会变化。若提供商拒绝密码登录，请使用其官方 OAuth/应用专用密码流程；本项目不会要求用户关闭双因素认证，也不会读取浏览器 Cookie。

## 开源边界

本仓库只包含通用代码和合成数据。请不要把真实简历、真实邮箱导出、个人联系方式、附件、密码、授权码、OAuth token 或公司内部数据提交到 GitHub。提交前运行：

```powershell
python -m unittest discover -s tests -v
node --test tests/test_recommendations.cjs
```

Node.js 仅用于运行前端回归测试，日常启动仍只需要 Python。推荐测试覆盖目录耗尽、跨批次去重、旧数据迁移、别名、邮件去重和进度导入。
